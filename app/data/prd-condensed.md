# PRD (condensed) — Provider Lookup & NPI Verification
Upstream: CMS NPPES NPI Registry API v2.1 (public, unauthenticated). Full text: prd.md.

## Problem
Enrollment & Credentialing onboards thousands of providers/year; every file starts with an NPI. Verification today is manual (NPPES web UI, eyeball, paste) with no record of what/when/by whom. Pain: typos survive intake (NPPES does not validate check digits — a Luhn-invalid NPI returns result_count:0, ambiguous with "not found"); name/taxonomy drift goes unnoticed; LOCATION vs MAILING addresses conflated; roster work (hundreds of NPIs) impractical one-by-one; ad-hoc scripts hammer the shared public API with no caching or back-off.

## Users
Dana (Enrollment Analyst: fast lookup, NPI confidence), Marcus (Credentialing Specialist: defensible timestamped evidence), Priya (Data Steward: batch verification, discrepancy exports), Lee (Compliance/Audit: searchable audit log), Sam (Platform Admin: access/cache/load control).

## Goals
1. Verify one provider in under 30s including documentation. 2. Disambiguate "not found": malformed NPI vs check-digit failure vs unregistered vs upstream failure. 3. Every verification evidentiary (who/when/query/NPPES response incl. last_updated/verdict). 4. Surface discrepancies (name, primary taxonomy, practice location, status). 5. Roster-scale: 500 NPIs/batch without abusing NPPES. 6. Good API citizen: cache, rate-limit, back off.
Non-goals: not a credentialing system of record; no NPPES write path; no auto-correction (flags only, humans decide); no bulk-file mirror; no external access; never imply licensure — "active NPI" does not mean credentialed.

## Requirements (P0 = Phase 1; P1 = Phase 2)
REQ-001 Direct NPI lookup + check-digit validation (P0): enter 10-digit NPI, retrieve record. Client AND server validate length/numeric (strip whitespace/hyphens) and the Luhn check digit with CMS 80840 prefix BEFORE any upstream call; distinct messages for not-10-digits vs check-digit-fails. Well-formed + zero results: "valid NPI format, not found in NPPES".
REQ-002 Individual search NPI-1 (P0): last_name required, optional first_name/state; enumeration_type=NPI-1. Trailing wildcard needs at least 2 leading chars (NPPES error 03); UI blocks shorter.
REQ-003 Organization search NPI-2 (P0): organization_name plus optional location filters; enumeration_type=NPI-2. Show legal business name, DBA other_names, authorized official name/title.
REQ-004 Filters + minimum-criteria guard (P0): taxonomy_description, city, state, postal_code (5 or 9 digits). Block state-as-sole-criterion client-side with explanation (NPPES error 07).
REQ-005 Paginated results, honest counts (P0): limit/skip; page sizes 10/25/50/100/200 (default 25, max 200). NPPES result_count = page size, NOT a total: UI shows "Showing X–Y", never "of N"; Next enabled on a full page. Depth cap 1,000 records, then prompt to narrow criteria.
REQ-006 Provider detail view (P0): NPI, enumeration type, status, enumeration date, last_updated; name/credential (NPI-1) or org data (NPI-2); primary taxonomy visually distinguished (code, description, license, state); LOCATION and MAILING addresses separate and labeled; phone; other_names; identifiers; endpoints; practiceLocations. ZIP+4 formatted. sole_proprietor YES: residence warning.
REQ-007 Verification vs enrollment record (P0): given NPI + submitted attributes (name, credential, primary taxonomy code, practice state/ZIP), per-field MATCH / MISMATCH / NOT_PROVIDED (case-insensitive, normalized; check all other_names; taxonomy vs all taxonomies, noting primary or not). Verdict: VERIFIED, REVIEW (any mismatch), FAILED (not found, deactivated, wrong enumeration type). Deactivated (basic.status != A) always FAILED. Saveable as evidence snapshot; export PDF + JSON.
REQ-008 Batch verification (P1): CSV up to 500 rows (npi required; optional name, taxonomy, state, ZIP): per-row REQ-007 verdicts. Async with progress, honors rate limits, tolerates partial failure (failed rows reported, not fatal), cancellable, downloadable CSV (verdict, per-field results, NPPES last_updated). Malformed rows reported with row numbers; never abort the batch.
REQ-009 Error handling (P0): NPPES validation errors arrive as HTTP 200 + Errors[] {description, field, number} — integration MUST treat presence of Errors as failure. Codes 03/05/06/07/17 map to field-level messages. Transport failures (timeout, 5xx, DNS, reset): bounded exponential backoff; surfaced as "NPPES is temporarily unavailable", never "no results". Unknown codes: generic message + raw description under details, logged.
REQ-010 Caching + visible freshness (P0): NPI lookups 24h; searches 1h; negatives 15min; errors never cached. Every result shows retrieved-at and NPPES last_updated. Verifier role can force refresh; verification snapshots always use a fresh fetch.
REQ-011 Upstream protection (P0): all NPPES traffic via server-side proxy, never browsers. Global max 4 concurrent, token bucket 5 req/s, single-flight dedup of identical in-flight requests, honor Retry-After, circuit breaker serving stale cache (flagged stale) where available. Limits configurable without redeploy.
REQ-012 Audit trail + evidence snapshots (P0): append-only log of every lookup, search, verification, batch run, export, forced refresh: user ID, role, UTC timestamp, action, normalized query params, result NPIs, verdict, cache hit/miss, request ID. Snapshots store full NPPES payload + sha256 + comparison result, immutable once written. 7-year retention. Searchable, filterable, exportable.
REQ-013 Access control (P0): corporate SSO (OIDC). Roles: Viewer (search, view), Verifier (+ verify, batch, refresh, export), Auditor (read-only audit log + snapshots), Admin (settings). Search activity is access-controlled and logged. Store nothing beyond cache + snapshots.

## Non-functional
p95 server overhead <= 150ms on cache hit; <= 3s end-to-end on cache miss. 99.5% business-hours availability with graceful stale degradation. WCAG 2.1 AA; verdicts never color-only. Current + previous Edge/Chrome/Safari. OWASP ASVS L2; CSV formula-injection-safe on export. Structured logs, metrics, alerting on circuit open.
